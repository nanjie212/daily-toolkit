# 云端留言板 — 部署指南（站长专用）

> 适用功能：**普通日常工具箱 → 社区留言板（云端共享）**
> 架构：前端（CloudStudio 静态托管） → Cloudflare Workers + D1（SQLite 边缘数据库）
> 安全红线：**前端零密钥**，D1 token 与 adminKey 仅存在于 Cloudflare 服务端，绝不进前端 bundle。

---

## 一、前置准备（站长需自行准备）

| 项目 | 说明 | 是否必须 |
|------|------|---------|
| Cloudflare 账号 | 免费注册 https://dash.cloudflare.com/sign-up | ✅ 必须 |
| `wrangler` 命令行 | 本地安装（`npm i -g wrangler` 或 `npx wrangler`） | ✅ 必须 |
| Node.js ≥ 18 | 本地已具备（项目运行环境） | ✅ 必须 |
| 管理员密钥（自定义） | 用于隐藏/删除留言，站长自行设定一个高强度字符串 | ✅ 必须（运行时输入） |
| Cloudflare API Token（可选） | 若希望**委托助手代为执行**部署命令，需提供此 Token | ⚠️ 可选 |

> ⚠️ 国内网络注意事项：Cloudflare 在大陆无官方节点，部分网络下访问偏慢或偶发不可达。
> 若你的访客以国内为主且对稳定性敏感，请知悉此限制（这是当初选定该方案时已知的权衡）。

---

## 二、本地安装 wrangler 并登录

```bash
# 安装（全局）
npm i -g wrangler
# 或临时使用
npx wrangler --version

# 登录 Cloudflare（浏览器授权）
wrangler login
```

登录成功后会把令牌写入本地 `~/.wrangler/`。**该令牌只存在你本地，不会进代码。**

---

## 三、创建 D1 数据库并拿到 database_id

```bash
wrangler d1 create daily_toolkit_community
```

执行后终端会输出一段类似：

```
[[d1_databases]]
binding = "DB"
database_name = "daily_toolkit_community"
database_id = "1a2b3c4d...（32 位十六进制）"
```

把其中的 `database_id` 复制，**回填到项目根目录的 `wrangler.toml`**，替换占位符：

```toml
[[d1_databases]]
binding = "DB"
database_name = "daily_toolkit_community"
database_id = "这里替换为你的真实 database_id"
```

---

## 四、建表（执行 schema.sql）

```bash
# 生产环境建表（--local=false 表示远端 D1）
wrangler d1 execute daily_toolkit_community --local=false --file=worker/schema.sql
```

如需在本地先验证，可加 `--local` 用本地 SQLite 试跑。

---

## 五、配置管理员密钥（隐藏/删除留言用）

```bash
wrangler secret put COMMUNITY_ADMIN_KEY
# 交互式输入你自定的高强度密钥（如：Tb#9kQ!2mZx...）
```

设置后该密钥以加密形式存于 Cloudflare，运行时通过 `env.COMMUNITY_ADMIN_KEY` 读取。
**不要把它写进任何前端代码、`.env` 或仓库。** 普通访客无此密钥，无法删除/隐藏他人留言。

---

## 六、部署 Worker

```bash
wrangler deploy
```

部署成功后，终端会给出 Worker 地址，形如：

```
https://daily-toolkit-community.<你的子域>.workers.dev
```

记下这个 URL，下一步要用。

---

## 七、配置前端 API 地址并构建

前端通过环境变量 `VITE_COMMUNITY_API` 指向 Worker。

**方式 A：构建时注入（推荐）**

在项目根目录创建 `.env`（或 `.env.production`），写入：

```env
VITE_COMMUNITY_API=https://daily-toolkit-community.<你的子域>.workers.dev
```

> ⚠️ `.env` 含的只是 Worker 的**公共 HTTPS 地址**，不是任何密钥，可安全提交/构建。

然后正常构建：

```bash
npm run build
```

**方式 B：CloudStudio/构建平台环境变量**

在 CloudStudio 的构建环境变量中设置 `VITE_COMMUNITY_API=<Worker URL>` 即可。

构建产物照常部署到 CloudStudio 静态托管（读 `dist/`）。

---

## 八、验证

1. 打开线上留言板页面，发一条留言 → 应出现在「所有人可见」的列表（换浏览器/设备也能看到）。
2. 点赞 / 鼓励 → 同一设备重复点会取消（按 deviceId 去重）。
3. 回复 → 追加到该留言下。
4. 管理隐藏：用 `DELETE https://<Worker>/api/messages/:id`，请求头带 `x-admin-key: <你的密钥>` → 该留言对所有人隐藏（软删除，数据保留）。
5. 故意发超长 / 含敏感词内容 → 应被拒绝（400）。
6. 60 秒内连发两条 → 第二条被限流（429）。

## 九、故障与降级说明（给站长）

- **Worker 不可用 / 未配置 API**：前端自动回退到本地 `safeStorage` 缓存，访客仍可见上次缓存的留言；发布时先写本地草稿，联网后自动同步。
- **CORS**：Worker 已处理 `OPTIONS` 预检并放行前端域。若后续锁定只允许 CloudStudio 域名，可把 `worker/index.ts` 的 `corsHeaders` 改为固定 `Access-Control-Allow-Origin`。
- **敏感词**：列表在 `worker/index.ts` 的 `BLOCKED_WORDS` 中维护，按需扩充。
- **限流参数**：新留言 60s/设备/IP 各 1 条，回复 60s 各 3 条，常量在 `worker/index.ts` 顶部可调。

## 十、委托助手自动部署（可选）

若你把 **Cloudflare API Token** 提供给助手，助手可代为执行上述
`wrangler login`（用 token 注入）→ `d1 create` → `d1 execute` → `secret put` → `deploy` 全流程。
在此之前请务必：
1. 仅在可信会话中提供 Token；
2. 明确 Token 的最小权限范围；
3. 部署后及时在 Cloudflare 控制台吊销/轮换该 Token。

> 注意：本仓库的代码实现阶段**不会**实际执行上述远程部署命令（需你的凭证），
> 仅交付可部署的代码与本文档。
